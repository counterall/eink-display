# Clock & Weather Dashboard

## 休息提醒与开始工作

- 工作时间不再固定为 09:00–17:00。工作日在工作时间区块点击「开始工作」，点击时刻（按分钟取整）即为上班时间，8 小时后下班；区块随后显示 8 小时进度条和「HH : MM 后下班」倒计时（见下文「左半部分布局」）。上班 / 下班时刻按主城市时间显示。上班时间保存在浏览器中，刷新后继续。
- 点击「开始工作」后弹出「新的一天开始啦 注意休息呀」窗口，只有右上角关闭按钮（Esc 同样可关闭）；此窗口与休息提醒设置无关，总会显示。
- 设置中的「休息提醒」默认关闭。开启后，仅在本次 8 小时工作时段内提醒：每次提醒窗口（包括上面的「新的一天」窗口）**关闭的时刻**起算 1 小时后弹出「Take a break ☕」，而不是整点。可选 10 / 15 / 30 分钟，「下次吧」或右上角关闭按钮立即关闭；「开始吧」切换为休息倒计时，倒计时结束自动关闭（以结束时刻起算下一小时），中途关闭（右上角关闭按钮或 Esc）则以关闭时刻起算。
- 休息倒计时显示为页面顶部居中（距顶约 1em）的一枚小型磨砂玻璃胶囊：只有剩余时间 `分:秒`（如 `09:59`，每秒更新，按结束时刻计算，向上取整到整秒）和下方细长圆角的已休息进度条，不显示「继续休息」或「分钟」字样（屏幕阅读器仍读出「继续休息 09:59」）。数字字号 4.2em，与下班倒计时使用同一套样式：经典样式为普通数字（冒号用强调色），翻页样式为两张翻页卡片（分 | 秒）。胶囊为半透明卡片色（约 45%）加背景模糊（`backdrop-filter: blur(18px) saturate(160%)`）、1px 浅色描边、柔和阴影和圆角；浅色系主题为白色磨砂，深色主题为烟灰色玻璃。休息期间页面不变暗，背后的内容照常可读可点（设置、主题切换、轮播等），轮播继续自动切换；只有胶囊本身响应点击。「Take a break」与「新的一天」窗口保持原样（居中、遮罩背景）。
- 到期的提醒会一直保留到被处理，设备休眠后唤醒仍会补弹；下一次提醒若晚于下班时间则不再弹出。倒计时保存结束时刻，刷新页面后继续；关闭提醒设置会同时关闭正在显示的休息窗口。
- 开启休息提醒后设置中多出「休息通知：关 / 开」（默认关，保存在设置中）。不支持 Notification API 的浏览器（如未添加到主屏幕的 iOS Safari）不显示此项、行为不变。选「开」时向浏览器申请通知权限，只有获准后才真正开启；权限被拒绝时此项保持「关」，并提示需在浏览器设置中允许本站通知。
- 开启后，每次按计划到期的休息提醒在页面不在眼前（标签页隐藏、窗口最小化，或窗口未获得焦点，例如在其他工作区或被其他程序遮挡）时额外弹出一条系统通知「Take a break ☕」（中英文相同，不含时长等信息），点击通知回到本页并关闭通知。每次提醒只判断一次：到期时页面在眼前则不发通知，之后再切走也不补发；已通知过的提醒（按到期时刻记录在 `kindle-break-v1` 的 `notifiedFor`）刷新页面或在另一个标签页中不会重复通知。设置中的「立即」、「新的一天」窗口和休息倒计时结束都不发通知。后台标签页的计时器会被浏览器节流，通知可能晚约 1 分钟；需 HTTPS 或 localhost，不支持 Android Chrome。

## fullscreen-time 分支

- 设置增加「右侧资讯栏：显示 / 隐藏（全屏时间）」，默认显示，旧设置自动兼容；选择会保存在浏览器中。
- 隐藏后时间区域占用 100% 可用宽度，放大基础字号和主时钟；在完整 1448 × 1072 CSS 视口下基础字号从 24 增至 29，经典主时钟约为 354px。其他视口按下文「布局与缩放」自动缩放，主页面不增加边框。
- 全屏时间模式指网页内部布局，不会强制隐藏浏览器地址栏或系统菜单。隐藏右栏时停止该组件的榜单轮询；GitHub 上的每日数据生成计划不受某个设备的显示选项影响。
- 第二城市右侧为工作时间区块，按**主城市当地时间**显示，界面显示用于计算的城市；交换主城市后时区随之变化。工作日（周一至周五）点击「开始工作」后的 8 小时内按分钟显示「HH : MM 后下班」（屏幕阅读器读作「离下班还有 HH : MM」，见下文「左半部分布局」）。
- 下班倒计时数字与第二城市时间统一字号（双栏 `3.3em`，全屏 `4.4em`；翻页卡片 `3.1em` / `3.8em`）。全屏模式的控制区移到右上角，避免挤压大字号的工作时间区块；双栏模式仍保留底部控制区。
- 主时钟、第二城市时间和下班倒计时共用小时 / 冒号 / 分钟组件及间距规则；两块之间以细竖线分隔，小视口适度收紧以避免溢出。
- 页面右上角的月亮 / 太阳按钮可切换深色模式（黑底白字）与最近使用的浅色主题（默认白底黑字），选择会保存在浏览器中；适用于双栏和全屏时间模式，且不影响右栏显隐。重新打开时会在 React 启动前应用已保存的深色背景，避免先显示白色加载画面。设置窗口在深色模式使用白色边框，主页面仍无边框。每个主题是 `<html>` 和页面根元素上的 `theme--<名称>` 类名（浅色无类名），类名只定义一组 CSS 变量（页面背景、正文、次要文字、强调色、卡片、边框、实心按钮、遮罩和翻页卡片颜色），其余样式统一使用 `var(--…)`；彩色主题见下文「功能」。
- 工作日尚未开始工作时显示「开始工作」按钮；当天 8 小时结束后显示「下班啦 好好休息！」，次日重新显示按钮。周六、周日优先全天显示「周末啦 不用上班！」（跨午夜仍在进行的工作时段继续倒计时）。英文界面使用对应英文提示。不额外识别法定节假日。
- 该区块使用现有时钟刷新，不增加网络请求；休眠恢复后重新按当前时间计算，倒计时不显示秒。
- `fullscreen-time` 与 `top-feeds` 分支均只构建验证，自动提交快照和 Pages 发布仍仅允许 `main`。

## 右侧轮播：GitHub 周榜与日榜

右侧 50% 是两张幻灯片的轮播：「GitHub · 本周热门 / Weekly trending」（第 1 张）与「GitHub · 今日热门 / Daily trending」（第 2 张），各为 GitHub Trending Top 5：仓库名称、最多两行简介、主要语言和本期新增 Stars（周榜「+N 本周 / this week」，日榜「+N 今日 / today」），保留官方榜单顺序，不改用仓库搜索或按 Stars 重排。界面中英文随设置切换，项目简介保留原文。点击仓库可打开项目页面。

- 每张幻灯片有各自的更新时间、离线 / 过期提示（两者均为超过 48 小时视为过期）；下方的说明与「查看官方周榜 / 日榜」链接跟随当前幻灯片（日榜链接为 `github.com/trending?since=daily`）。
- 每隔「轮播间隔」自动切到下一张，最后一张之后回到第一张。计时从**上一次切换**算起，任何手动切换（箭头、圆点、键盘、滑动）都会重新计时。复用每分钟一次的时钟，没有额外的计时器，因此切换最多可能晚约 1 分钟。刷新页面后总是从周榜开始，不记住当前幻灯片。
- 设置窗口、「Take a break」或「新的一天」窗口打开时（休息倒计时胶囊不暂停）、鼠标停在轮播上时，以及键盘焦点在轮播内时暂停自动切换（避免焦点所在的链接被切走）；离开后若已到时间，在下一次分钟刷新时切换。
- 切换为约 400 ms 的水平滑动（ease-out），两次切换之间完全静止；系统要求减少动态效果（`prefers-reduced-motion: reduce`）时直接切换。
- 左右两侧中部是小圆形的上一张 / 下一张图标按钮：可见圆盘 1.6em（1448 × 1072 下约 38px，不小于 32px），箭头图标 1em（不小于 18px），距左右边缘 0.25em；圆盘外有透明的点击区域，不小于 44 × 44 CSS 像素。使用鼠标时悬停在轮播上（或键盘焦点在轮播内，鼠标点击后不算）才以完全不透明显示；触屏设备（`hover: none`）始终显示，但整个按钮为 50% 不透明、无边框，按下或获得键盘焦点时恢复完全不透明（按下时为主题色实心填充），并可左右滑动切换，滑动不会同时打开仓库链接。焦点在轮播内时，键盘左 / 右方向键切换；焦点原在仓库链接上时移到新幻灯片的圆点。
- 页脚上方居中为圆点，一张一个：当前为实心、其余为空心，可点击，点击区域不小于 44 px；屏幕阅读器读作「第 1 张，共 2 张：本周热门」/「Slide 1 of 2: weekly trending」并标明当前项。
- 两张幻灯片并排放在同一轨道中，面板高度取较高的一张，切换时下方内容不跳动；屏幕外的幻灯片设为 `inert` 和 `aria-hidden`（不可聚焦、不被朗读）。竖屏堆叠布局中轮播位于时钟下方，全宽，箭头与圆点相同。自动适配检查同时考虑两张幻灯片的高度。
- 箭头、圆点及悬停 / 焦点状态使用各主题的颜色变量。
- 隐藏右栏（全屏时间）时没有轮播，不自动切换，也不轮询任何榜单。
- 设置中「右侧资讯栏」下方为「轮播间隔 / Carousel interval」：10 分钟（默认）/ 30 分钟 / 1 小时，没有「关闭」选项，只在右栏显示时出现。保存在 `kindle-settings-v1` 的 `carouselInterval`（10 | 30 | 60），旧设置或无法识别的值按 10 处理；修改从下一次切换起生效。
- 要增加第三张幻灯片，只需在 `src/carousel.js` 的 `CAROUSEL_SLIDES` 中加一项（另需该榜单的数据配置与文字）。

左侧两座城市的名称行均采用「城市名称靠左、日出日落图标与时间居中、天气图标及当前气温靠右」的布局，今日最低–最高温在当前气温下方以较小字号辅助显示。当前气温为最近一次天气更新时的实况数据，每两小时更新，不表示逐分钟实时数据。日出日落不显示文字标签，但保留无障碍名称和悬停提示。极昼、极夜使用太阳 / 月亮图标和 24h 提示。

天气按赫尔辛基时间每 2 小时更新（00:00、02:00、04:00…），请求当前气温、当前天气代码和日预报，不再获取或显示逐小时温度曲线及降水概率。没有当前气温的旧缓存会在页面恢复时自动补取数据。手动刷新功能已删除，统一更新时间和自动更新状态位于左侧底部。主页面不显示黑色实线边框或分隔线，键盘焦点使用虚线轮廓；设置窗口保留黑色实线外框、下拉框 / 按钮边框、内部分隔线和焦点轮廓。

`top-feeds` / `fullscreen-time` 推送和手动运行只执行数据获取、测试、构建和 artifact 上传，不发布 Pages，也不自动提交文件。只有 `main` 允许持久保存榜单和发布主站；定时任务仅在工作流进入默认分支后生效。

面向现代桌面和平板浏览器的时钟、天气与 GitHub 周榜 / 日榜看板（不再支持 Kindle 或其他电子墨水屏）。React + Vite + pnpm，纯静态网页，无自建后端、无需天气 API key。

## 本地运行

安装 Node.js 22 或更高版本及 pnpm 10，然后运行：

```sh
pnpm install
pnpm refresh:trending
pnpm dev
```

打开终端显示的地址。开发服务器只用于开发；发布前用 `pnpm build && pnpm preview` 检查生产构建。

仓库已包含一份真实榜单快照，离线构建不要求先运行抓取命令。`pnpm refresh:trending` 只更新本地数据文件，不会提交、推送或部署。

```sh
pnpm test
pnpm lint:css
pnpm build
pnpm preview
```

## 功能

- 默认主城市 Helsinki、第二城市 Xi’an，主城市时间最大，每分钟更新。左侧时间与城市天气区域、右侧榜单轮播区域按 50% / 50% 分配。
- 布局与缩放：页面不旋转，始终铺满浏览器视口；所有尺寸以 em 表示，基础字号按 CSS 视口计算（`src/layout.js`）：
  - 横向且显示右栏（双栏）：以 1448 × 1072 为参考，基础字号 24px × min(宽 / 1448, 高 / 1072)。1448 × 1072 时与原来完全相同；1280 × 800 约 17.9px，1920 × 1080 约 24.2px，2560 × 1440 约 32px。
  - 竖向且显示右栏（堆叠，平板竖放）：时间区在上、周榜移到下方占满宽度，以 1072 × 1720 为参考（768 × 1024 约 14.3px）；周榜每条简介只显示一行、行距略收紧。万一仍放不下，自动适配会缩小页面，页面也可上下滚动，不会裁掉内容。
  - 隐藏右栏（全屏时间）：基础字号 29px；横向以 1448 × 1072、竖向以 1200 × 1448 为参考，保证竖放时第二城市与工作时间两块仍能并排。
  - 基础字号最小为参考值的 1/3、最大为 2 倍。宽度小于 650px 时使用更紧凑的内边距。
  - 自动适配：页面没有手动缩放。内容超出页面（或彩色主题的周榜卡片、时钟列、两块时间区域）时，从 100% 起每次缩小 10%，直到放得下或到 70%，从不放大到 100% 以上。视口尺寸、布局模式、语言、时间格式、主题或时钟样式变化后重新从 100% 开始检查，因此平板转到竖向再转回横向不会一直变小。
  - 已删除「放大 / 缩小」按钮及缩放设置（原为 Kindle 而设）；旧设置中保存的 `zoom` 会被忽略，下次保存时消失（例如原来保存的 120% 现在按 100% 显示）。
  - 设置面板底部显示实际 CSS 视口与像素比。
- 左半部分布局（双栏、全屏时间模式，经典与翻页样式相同）：
  - 上方为主城市：城市名称行在日期栏下方，主时钟（卡片）在剩余高度中垂直居中，不在下方留出大片空白。双栏时主时钟受列宽限制（左栏右侧内边距由 2em 减为 1.4em），经典数字由视口宽度的 17% 增至 18%，翻页卡片由 10.5% 增至 10.8%；全屏时间模式下第二城市与工作时间并排，主时钟按视口高度放大（翻页 20.5% → 23%，经典 31% → 33%）。
  - 下方为左右等宽的两块：中间一条细竖线，与主时钟之间一条细横线，线条使用各主题的边框 / 分隔线颜色（浅色黑、深色白、彩色主题见下表）。
  - 左块「第二城市 / SECOND CITY」：灰色小标题，城市名称与天气同一行，日出日落另起一行，下方为时间（卡片）及其右侧的「今天」；两地不在同一天时改为两行小字「年 / 月-日」（如 2026 / 11-25），以便在半宽中放在时间右侧。
  - 右块「工作时间 · 主城市」/「Work hours · 城市」：工作中显示 8 小时进度条，从上班时刻到下班时刻，按已工作时间 / 8 小时填充；进度条下方左端为上班时刻、右端为下班时刻、中间为「已工作 h:mm」/「worked h:mm」（按分钟取整，与倒计时相加恰为 8 小时）。再下方为倒计时（卡片）及其后的「后下班」/「to go」，与左块的时间卡片底部对齐。屏幕阅读器仍读作「离下班还有 01:27」/「Off work in 01:27」。
  - 进度条为静态百分比宽度，随每分钟时钟刷新，没有动画或过渡。未开始时右块显示「开始工作」按钮；下班后和周末显示原有提示，字号缩小以适应半宽。
  - 自动适配检查同时确认两块中的时间不超出各自范围。
- 主城市名称行从日期栏下方开始排列；大时钟的小时、冒号、分钟独立排版并保持紧凑间距，12 小时制的 AM / PM 放在数字下方右侧，不挤占数字宽度。
- 两地时间使用本地打包的免费 Roboto Condensed 窄体数字字体（SIL OFL 1.1），提供 WOFF2 和兼容旧浏览器的 WOFF，不依赖 Google Fonts 或字体 CDN。主时钟提高字号，小时、冒号、分钟采用固定的紧凑间距，不再拉伸铺满整列；第二城市时间明显放大，但保持主次层级。字体加载失败时回退到 Arial。许可随页面发布，见 `public/roboto-condensed-license.txt`。
- 第二城市采用城市名在上、时间在下的纵向布局，城市名称字号与主城市名称一致，时间适度放大，日期提示保留在时间旁；主城市仍保持最大的时间字号。
- 城市预设：赫尔辛基、西安、伦敦、罗弗敦群岛（Svolvær）、大阪。旧设置中的北京自动替换成西安，保留原有主次顺序；不会把北京天气缓存用作西安天气。
- 日期与星期之间显示主城市当天对应的中国农历日期（如「农历九月廿八」「农历闰六月初一」），始终使用中文，不随界面语言切换；英文界面顺序为「星期 · 农历 · 日期」。在主城市午夜随公历日期一起切换，同样由 `lunar-javascript` 本地计算。
- 日期与星期旁显示当前中国节气，始终保留中文名称，不随界面语言切换；按北京时间的实际交节时刻切换，非节气当天也显示当前所处节气。使用 `lunar-javascript` 在本地计算，无需联网；计算结果缓存至下一次交节，避免每分钟重复运算。

## GitHub Pages

项目使用 `.github/workflows/deploy.yml`。修改工作流不会在本地自动发布，必须推送到相应分支或在 GitHub 上手动运行。

1. 创建 GitHub 仓库，将项目推送到 `main` 分支（包含 `pnpm-lock.yaml`）。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. `main` 工作流自动获取榜单、测试、构建并发布 `dist/`。`top-feeds` 构建不会发布 Pages。完成发布后在 Pages 页面查看网址。
   只修改 Markdown 文件（如 `README.md`、`CLAUDE.md`）的推送或合并的 PR 不会触发工作流，以免无意义的构建和发布；只要同时改了其他文件仍会照常运行。每日定时任务和手动运行不受影响。
4. 在桌面或平板浏览器打开该网址。首次打开需要联网加载页面和天气。

`base: './'` 兼容仓库子路径，无需硬编码仓库名。若用于组织项目，正式部署前请与 infra 团队确认托管规范。

## 周榜与日榜的数据生成与每日更新

```text
GitHub Actions / 本地 pnpm refresh:trending
  → 读取 https://github.com/trending?since=weekly 与 https://github.com/trending?since=daily
  → 生成 public/data/github-trending.json（周榜）与 public/data/github-trending-daily.json（日榜）
  → pnpm build 将 JSON 复制到 dist/data/
  → GitHub Pages 提供同域静态 JSON
  → 浏览器每小时检查一次两个 JSON，恢复页面时按需补查
```

- HTML 只在 Node.js 脚本中解析（Cheerio 为构建依赖），浏览器不抓取 GitHub HTML（github.com/trending 不返回 CORS 头，GitHub 也没有 Trending API），不需要 CORS 代理、额外服务器、API key 或浏览器端 GitHub token。
- 脚本严格校验五条完整、无重复的仓库数据、本期新增 Stars（周榜解析「N stars this week」为 `weeklyStars`，日榜解析「N stars today」为 `dailyStars`）、排名和 GitHub 仓库链接。两个榜单各自抓取、校验和原子写入：一个失败时另一个照常更新，失败的那个保留上次成功的文件。源码变动、403 / 429、网络错误或结果不完整时，不覆盖已保存文件，也不伪造新的更新时间。某个榜单没有有效快照且抓取失败时，命令最终会失败（另一个榜单仍已写入），避免发布空榜单。
- `public/data/github-trending.json` 与 `public/data/github-trending-daily.json` 都应提交到仓库；不能加入 `.gitignore`。它是 Actions 全新运行环境中的持久备份，而非依赖上一次 runner 的临时目录或缓存。
- 合并到 `main` 后，工作流计划在每天 **06:17 UTC** 运行（赫尔辛基冬季 08:17、夏季 09:17）。GitHub 定时任务可能延迟，不是严格准点调度。推送 `main` 或手动运行 `main` 也会刷新。
- `main` 的构建测试通过后，仅把这两个 JSON 文件的变化以「chore: refresh Trending snapshots」自动提交回 `main`，同一工作流接着发布已构建的网站。不依赖 bot 提交再触发第二个工作流，也不执行 force push。
- 因为定时任务会产生快照 bot 提交，本地继续开发前应先同步远端 `main`；榜单文件发生合并冲突时可用脚本重新生成，不要强制覆盖远端历史。
- 自动保存需要工作流的 `contents: write` 权限。仓库或组织分支保护若禁止 bot 直接推送，持久化步骤会明确失败，需要仓库管理员安排允许的更新方式；不要为此关闭分支保护。
- 功能分支与 `main` 使用不同并发组，功能分支构建不会取消主站部署。发布 job 和自动提交步骤均限定为 `refs/heads/main`。
- 浏览器为两个榜单分别保留最后成功快照（`kindle-trending-weekly-v1`、`kindle-trending-daily-v1`），页面打开时就读取两个榜单，切换幻灯片不会出现加载状态；读取 JSON 失败不清空榜单，也不让旧部署文件覆盖更新的浏览器缓存。超过 48 小时显示延迟提示，时间使用主城市时区。
- 当前数据是官方网页快照，不是 GitHub 官方 Trending API；页面结构仍可能变化，需要维护解析器。组织项目启用定时任务与自动提交前请联系 infra 团队确认规范。

## 目标浏览器

只支持现代桌面和平板浏览器：`package.json` 中的 browserslist 为 Chrome、Edge、Firefox、Safari、iOS Safari 的最近两个版本及 Firefox ESR。stylelint（`pnpm lint:css`）按此列表检查 CSS；JavaScript 使用 Vite 的默认现代构建目标，不再生成 legacy 代码块和 polyfill。CSS 可以使用变量、Grid、Flex `gap`、动画和过渡。

城市时间由 `Intl.DateTimeFormat` 按各城市的 IANA 时区（`Europe/Helsinki`、`Asia/Shanghai`、`Europe/London`、`Europe/Oslo`、`Asia/Tokyo`）计算，夏令时规则由浏览器的时区数据决定，不依赖设备本身的时区设置；时间准确性仍取决于设备的系统时钟。天气刷新时段始终按赫尔辛基时间，工作时段按主城市时间，节气按北京时间。

天气和周榜请求使用 `fetch`，以 `AbortController` 实现超时（天气 20 秒、周榜 15 秒）。

localStorage 键名保留原来的 `kindle-` 前缀（`kindle-settings-v1`、`kindle-work-v1`、`kindle-break-v1`、`kindle-weather-v1`、`kindle-trending-weekly-v1`、`kindle-trending-daily-v1`），以便已保存的设置和缓存继续有效。

## 天气来源与边界

天气由 [Open-Meteo](https://open-meteo.com/) 提供，免费开放接口适合个人非商业使用，遵守其[使用条款](https://open-meteo.com/en/terms)与[许可说明](https://open-meteo.com/en/licence)。发布到商业环境或大量设备前应重新核对额度与授权。

页面设置面板保留来源链接。浏览器直接向 API 请求，两座城市通常各一次请求 / 刷新时段。不是分钟级实时天气，也不是后台推送。断网后已打开的页面能继续显示时间及缓存，但本项目没有实现离线加载整个网页的 Service Worker。
