# Kindle Clock & Weather

## fullscreen-time 分支

- 设置增加「右侧资讯栏：显示 / 隐藏（全屏时间）」，默认显示，旧设置自动兼容；选择会保存在浏览器中。
- 隐藏后时间区域占用 100% 可用宽度，放大基础字号和主时钟；在完整 1448 × 1072 CSS 视口下基础字号从 24 增至 26，主时钟约为 332px。较小视口自动缩放，主页面不增加边框或动画。
- 全屏时间模式指网页内部布局，不会强制隐藏 Kindle 地址栏或系统菜单。隐藏右栏时停止该组件的榜单轮询；GitHub 上的每日数据生成计划不受某个设备的显示选项影响。
- 第二城市下方增加工作时间区块，按**主城市当地时间**计算，界面显示用于计算的城市；交换主城市后时区随之变化。工作日周一至周五 09:00（含）至 17:00（不含）按分钟显示「离下班还有 HH : MM」。
- 下班倒计时数字与第二城市时间统一使用 `4.8em` 字号；说明、工作时段和休息 / 周末提示同步放大。全屏模式的控制区移到右上角，避免挤压大字号的工作时间区块；双栏模式仍保留底部控制区。
- 主时钟、第二城市时间和下班倒计时共用小时 / 冒号 / 分钟组件及间距规则；工作区块与第二城市之间增加留白，小视口适度收紧以避免溢出。
- 页面右上角的月亮 / 太阳按钮可切换白底黑字与黑底白字，选择会保存在浏览器中；适用于双栏和全屏时间模式，且不影响右栏显隐。重新打开时会在 React 启动前应用已保存的深色背景，避免先显示白色加载画面。设置窗口在深色模式使用白色边框，主页面仍无边框。使用兼容旧浏览器的类名样式，而非依赖 CSS 变量或整体滤镜反色。
- 工作日 17:00–次日 09:00 显示「下班啦 好好休息！」；周六、周日优先全天显示「周末啦 不用上班！」。英文界面使用对应英文提示。不额外识别法定节假日。
- 该区块使用现有时钟刷新，不增加网络请求；休眠恢复后重新按当前时间计算，倒计时不显示秒。
- `fullscreen-time` 与 `top-feeds` 分支均只构建验证，自动提交快照和 Pages 发布仍仅允许 `main`。

## top-feeds 分支：GitHub 周榜

右侧 50% 显示 GitHub Trending 周榜 Top 5：仓库名称、最多两行简介、主要语言和本周新增 Stars，保留官方榜单顺序，不改用仓库搜索或按 Stars 重排。界面中英文随设置切换，项目简介保留原文。点击仓库可打开项目页面。

左侧两座城市的名称行均采用「城市名称靠左、日出日落图标与时间居中、天气图标及当前气温靠右」的布局，今日最低–最高温在当前气温下方以较小字号辅助显示。当前气温为最近一次天气更新时的实况数据，每两小时更新，不表示逐分钟实时数据。日出日落不显示文字标签，但保留无障碍名称和悬停提示。极昼、极夜使用太阳 / 月亮图标和 24h 提示。

天气按赫尔辛基时间每 2 小时更新（00:00、02:00、04:00…），请求当前气温、当前天气代码和日预报，不再获取或显示逐小时温度曲线及降水概率。没有当前气温的旧缓存会在页面恢复时自动补取数据。手动刷新功能已删除，统一更新时间和自动更新状态位于左侧底部。主页面不显示黑色实线边框或分隔线，键盘焦点使用虚线轮廓；设置窗口保留黑色实线外框、下拉框 / 按钮边框、内部分隔线和焦点轮廓。

`top-feeds` / `fullscreen-time` 推送和手动运行只执行数据获取、测试、构建和 artifact 上传，不发布 Pages，也不自动提交文件。只有 `main` 允许持久保存榜单和发布主站；定时任务仅在工作流进入默认分支后生效。

为 6 寸 Kindle Paperwhite 设计的黑白横向看板。React + Vite + pnpm，纯静态网页，无自建后端、无需天气 API key。

## 本地运行

安装 Node.js 22 或更高版本及 pnpm 10，然后运行：

```sh
pnpm install
pnpm refresh:trending
pnpm dev
```

打开终端显示的地址。开发服务器只用于开发；旧 Kindle 应测试生产构建，不要直接使用 Vite 的开发模式。

仓库已包含一份真实榜单快照，离线构建不要求先运行抓取命令。`pnpm refresh:trending` 只更新本地数据文件，不会提交、推送或部署。

```sh
pnpm test
pnpm lint:css
pnpm build
pnpm check:legacy
pnpm preview
```

## 功能

- 默认主城市 Helsinki、第二城市 Xi’an，主城市时间最大，每分钟更新。左侧时间与城市天气区域、右侧周榜资讯区域按 50% / 50% 分配。
- 以 1072 × 1448 的 Kindle 屏幕为适配参考（横向 1448 × 1072），字号和按钮跟随浏览器可用视口缩放，不强制使用物理像素宽高。完整参考视口下基础字号为 24 CSS px；设备像素比、地址栏和浏览器缩放导致可用区域较小时会相应调整。设置面板显示实际 CSS 视口、旋转后的布局尺寸和像素比，方便实机核对。
- 主城市从日期栏下方开始排列，不做垂直居中；大时钟的小时、冒号、分钟独立排版并保持紧凑间距，12 小时制的 AM / PM 放在数字下方右侧，不挤占数字宽度。
- 两地时间使用本地打包的免费 Roboto Condensed 窄体数字字体（SIL OFL 1.1），提供 WOFF2 和兼容旧浏览器的 WOFF，不依赖 Google Fonts 或字体 CDN。主时钟提高字号，小时、冒号、分钟采用固定的紧凑间距，不再拉伸铺满整列；第二城市时间明显放大，但保持主次层级。字体加载失败时回退到 Arial。许可随页面发布，见 `public/roboto-condensed-license.txt`。
- 第二城市采用城市名在上、时间在下的纵向布局，城市名称字号与主城市名称一致，时间适度放大，日期提示保留在时间旁；主城市仍保持最大的时间字号。
- 城市预设：赫尔辛基、西安、伦敦、罗弗敦群岛（Svolvær）、大阪。旧设置中的北京自动替换成西安，保留原有主次顺序；不会把北京天气缓存用作西安天气。
- 日期与星期之间显示主城市当天对应的中国农历日期（如「农历九月廿八」「农历闰六月初一」），始终使用中文，不随界面语言切换；英文界面顺序为「星期 · 农历 · 日期」。在主城市午夜随公历日期一起切换，同样由 `lunar-javascript` 本地计算。
- 日期与星期旁显示当前中国节气，始终保留中文名称，不随界面语言切换；按北京时间的实际交节时刻切换，非节气当天也显示当前所处节气。使用 `lunar-javascript` 在本地计算，无需联网；计算结果缓存至下一次交节，避免每分钟重复运算。
- 「交换城市」交换两地时间及名称行内的天气、日出日落，不改变系统时区；已有天气缓存可直接复用。
- 设置中可选中文 / English、12 / 24 小时制和城市，独立记住各项选择。
- 主页面控制区仅保留交换城市、设置图标及天气更新时间，不提供手动刷新；双栏模式位于左侧底部，全屏时间模式位于右上角。设置面板的「完成」位于左下方。
- 主页面的交换城市、设置使用双向箭头、齿轮图标按钮；点击区域跟随布局缩放，最小为 44 × 44 CSS 像素，在完整 1448 × 1072 CSS 视口下约为 82 × 82。保留中英文悬停提示及无障碍名称。
- 两地共用的「更新于」位于左侧底部，按主城市时区显示。取两地成功更新时刻中较早的一个，避免仅一地刷新成功时误报整体已更新；部分失败、断网及过期提示也在此处集中显示。任一城市尚无数据时，统一更新时间显示为「—」。
- 默认「自动横向」：浏览器视口为竖向时将网页顺时针旋转 90°，横向时不旋转。也可明确选择不旋转、顺时针或逆时针。
- 两地天气图标和主要温度为最近更新时的实况；较小的温度范围表示各自当地日期的整日最低–最高温。
- 天气按照固定的**赫尔辛基时间每 2 小时（00:00、02:00、04:00…）**检查更新；交换城市不改变这个日程。首次打开、增加城市及失败后的自动重试可额外请求。
- API 每次获取今天与明天的预报，避免午夜产生额外的例行请求。
- 缓存使用 localStorage，更新失败保留旧数据，明确标记过期；失败后退避 15 分钟。无缓存时显示错误，时间仍可用。
- 两地日出日落位于各自城市名称行中央，以图标和时间显示，不显示日出日落文字；极昼 / 极夜显示太阳 / 月亮图标和 24h 提示。
- 日出日落及晴、多云、阴、雾、雨、雪、雷暴、冰雹采用免费 [Lucide](https://lucide.dev/) 黑白 SVG 图标，保留中文 / 英文天气无障碍名称与悬停提示。只打包所用图标，无需图标字体、CDN 或额外网络请求。许可说明随构建一起发布，见 `public/lucide-license.txt`。

## GitHub Pages

项目使用 `.github/workflows/deploy.yml`。修改工作流不会在本地自动发布，必须推送到相应分支或在 GitHub 上手动运行。

1. 创建 GitHub 仓库，将项目推送到 `main` 分支（包含 `pnpm-lock.yaml`）。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. `main` 工作流自动获取榜单、测试、构建并发布 `dist/`。`top-feeds` 构建不会发布 Pages。完成发布后在 Pages 页面查看网址。
4. Kindle 浏览器打开该网址。首次打开需要联网加载页面和天气。

`base: './'` 兼容仓库子路径，无需硬编码仓库名。若用于组织项目，正式部署前请与 infra 团队确认托管规范。

## 周榜的数据生成与每日更新

```text
GitHub Actions / 本地 pnpm refresh:trending
  → 读取 https://github.com/trending?since=weekly
  → 生成 public/data/github-trending.json
  → pnpm build 将 JSON 复制到 dist/data/
  → GitHub Pages 提供同域静态 JSON
  → Kindle 每小时检查一次 JSON，恢复页面时按需补查
```

- HTML 只在 Node.js 脚本中解析（Cheerio 为构建依赖），Kindle 不抓取 GitHub HTML，不需要 CORS 代理、额外服务器、API key 或浏览器端 GitHub token。
- 脚本严格校验五条完整、无重复的仓库数据、周榜 Stars、排名和 GitHub 仓库链接。源码变动、403 / 429、网络错误或结果不完整时，不覆盖已保存文件，也不伪造新的更新时间。首轮没有有效快照且抓取失败时，命令会失败，避免发布空榜单。
- `public/data/github-trending.json` 应提交到仓库；不能加入 `.gitignore`。它是 Actions 全新运行环境中的持久备份，而非依赖上一次 runner 的临时目录或缓存。
- 合并到 `main` 后，工作流计划在每天 **06:17 UTC** 运行（赫尔辛基冬季 08:17、夏季 09:17）。GitHub 定时任务可能延迟，不是严格准点调度。推送 `main` 或手动运行 `main` 也会刷新。
- `main` 的构建测试通过后，仅把该 JSON 文件的变化自动提交回 `main`，同一工作流接着发布已构建的网站。不依赖 bot 提交再触发第二个工作流，也不执行 force push。
- 因为定时任务会产生快照 bot 提交，本地继续开发前应先同步远端 `main`；榜单文件发生合并冲突时可用脚本重新生成，不要强制覆盖远端历史。
- 自动保存需要工作流的 `contents: write` 权限。仓库或组织分支保护若禁止 bot 直接推送，持久化步骤会明确失败，需要仓库管理员安排允许的更新方式；不要为此关闭分支保护。
- 功能分支与 `main` 使用不同并发组，功能分支构建不会取消主站部署。发布 job 和自动提交步骤均限定为 `refs/heads/main`。
- 浏览器独立保留最后成功快照；读取 JSON 失败不清空榜单，也不让旧部署文件覆盖更新的浏览器缓存。超过 48 小时显示延迟提示，时间使用主城市时区。
- 当前数据是官方网页快照，不是 GitHub 官方 Trending API；页面结构仍可能变化，需要维护解析器。组织项目启用定时任务与自动提交前请联系 infra 团队确认规范。

## Kindle 实机检查

已知屏幕分辨率为 1072 × 1448，具体型号未知，现代浏览器中的验证**不能证明旧 Kindle 一定兼容**。

1. 打开生产网页，确认中文字体、大时钟、两地天气和右侧五条周榜项目都能显示。
2. 横着摆放 Kindle，按需选择顺时针 / 逆时针。旋转只影响网页，地址栏、原生下拉菜单和系统键盘不会随网页旋转。
3. 测试交换城市、中英文、12 / 24 小时制，重新打开后确认设置被保留。
4. 尽量收起浏览器工具栏，检查六寸屏的可用高度、按钮大小及图表字号。在设置底部查看实际 CSS 视口与像素比；这些数值可能小于物理屏幕分辨率，属于正常情况。
5. 断网跨过天气自动更新时段，应保留缓存并显示更新失败；重新联网后按自动重试策略恢复，不提供手动刷新按钮。
6. 让设备休眠并唤醒，确认时间和天气补查正常。网页不能保证阻止 Kindle 自动休眠，也无法在浏览器关闭或休眠时执行定时任务。
7. 核对榜单更新时间；断网后已打开页面的榜单应保留，恢复网络后按读取 / 重试策略补查。页面不会自动翻页或滚动。

生产构建包含 legacy JavaScript 与运行时 polyfill，目标为 Safari 9 / Chrome 49 及以上。CSS 避免 Grid、Flex gap 和动画；仍需设备支持基础 Flexbox、SVG、HTTPS、跨域 XHR 及 JavaScript。更旧或受限的 Kindle WebKit 可能需要后续适配，legacy 构建不能补齐浏览器渲染或 TLS 能力。

时钟不依赖设备的系统时区或 `Intl`：五个预设城市使用固定偏移及现行欧盟夏令时规则。如果未来夏令时政策发生变化，需要更新 `src/model.js`。时间准确性仍取决于 Kindle 的系统时钟。

## 天气来源与边界

天气由 [Open-Meteo](https://open-meteo.com/) 提供，免费开放接口适合个人非商业使用，遵守其[使用条款](https://open-meteo.com/en/terms)与[许可说明](https://open-meteo.com/en/licence)。发布到商业环境或大量设备前应重新核对额度与授权。

页面设置面板保留来源链接。浏览器直接向 API 请求，两座城市通常各一次请求 / 刷新时段。不是分钟级实时天气，也不是后台推送。断网后已打开的页面能继续显示时间及缓存，但本项目没有实现离线加载整个网页的 Service Worker。

## 文件

- `src/main.jsx`：入口，仅挂载 `src/App.jsx`。
- `src/App.jsx`：主界面、设置保存、主题与每分钟时钟（同时驱动天气检查）。
- `src/Settings.jsx`、`src/useViewport.js`：设置窗口与视口尺寸监听。
- `src/useWeather.js`：天气缓存读取、按时段请求和失败退避（判断逻辑为可测试的纯函数）。
- `src/i18n.js`：全部中英文界面文字，测试保证两种语言的键一致。
- `scripts/check-legacy.mjs`：构建后检查旧版浏览器代码块中没有 Safari 9 / Chrome 49 不支持的语法（`pnpm check:legacy`）。
- `.stylelintrc.json`：按 `package.json` 的 browserslist 检查 CSS 兼容性，并禁止动画、过渡和滤镜（`pnpm lint:css`）。
- `src/styles.css`：黑白看板和六寸屏紧凑样式。
- `src/CityHeading.jsx`：两地城市名称、居中日出日落及右对齐的当前气温与日温度范围。
- `src/CityHeading.test.jsx`：名称行排列、当前气温、12/24 小时日照事件及极昼极夜测试。
- `scripts/refresh-trending.mjs`：抓取官方 HTML、校验和原子写入快照，失败时保留旧文件。
- `public/data/github-trending.json`：已保存的最后一次成功周榜快照，随网站部署。
- `src/trendingData.js`：前后端共用的数据格式与仓库链接校验。
- `src/trending.js`、`src/useTrending.js`：同域 JSON 请求、定期检查和浏览器缓存。
- `src/TrendingFeed.jsx`：无边框周榜列表与更新时间、离线和过期提示。
- `src/layout.js`：1072 × 1448 Kindle 参考布局、CSS 视口缩放与旋转定位。
- `src/layout.test.js`：原始分辨率、不同像素比对应的 CSS 视口、工具栏占用空间及旋转测试。
- `src/workday.js`、`src/WorkdayBlock.jsx`：主城市工作时间判断、下班倒计时与周末 / 休息提示。
- `src/workday.test.js`、`src/WorkdayBlock.test.jsx`：09:00 / 17:00 边界、分钟取整、周末、时区及提示文字测试。
- `src/model.js`：城市、时区、语言日期、刷新时段和预报处理。
- `src/weather.js`：带 20 秒超时的天气请求与响应校验。
- `src/WeatherIcon.jsx`：天气代码与本地 SVG 图标的对应显示。
- `src/weatherPresentation.test.jsx`：统一更新时间、部分失败状态与天气图标测试。
- `src/solarTerms.js`：节气计算、北京时间转换与固定中文名称；以及按主城市日期计算的中文农历日期。
- `src/solarTerms.test.js`：交节时刻、跨年、闰年及 24 节气名称测试。
- `src/model.test.js`：时区 / 夏令时、日期切换、缓存容错、预报与 API 单元测试。
- `vite.config.js`：静态子路径、旧浏览器构建和可独立缓存的节气库分包。
