# Kindle Clock & Weather

为 6 寸 Kindle Paperwhite 设计的黑白横向看板。React + Vite + pnpm，纯静态网页，无自建后端、无需天气 API key。

## 本地运行

安装 Node.js 22 或更高版本及 pnpm 10，然后运行：

```sh
pnpm install
pnpm dev
```

打开终端显示的地址。开发服务器只用于开发；旧 Kindle 应测试生产构建，不要直接使用 Vite 的开发模式。

```sh
pnpm test
pnpm build
pnpm preview
```

## 功能

- 默认主城市 Helsinki、第二城市 Xi’an，主城市时间最大，每分钟更新。时间与天气两列按 60% / 40% 分配。
- 主城市从日期栏下方开始排列，不做垂直居中；大时钟的小时、冒号、分钟独立排版并保持紧凑间距，12 小时制的 AM / PM 放在数字下方右侧，不挤占数字宽度。
- 两地时间使用本地打包的免费 Roboto Condensed 窄体数字字体（SIL OFL 1.1），提供 WOFF2 和兼容旧浏览器的 WOFF，不依赖 Google Fonts 或字体 CDN。主时钟提高字号，小时、冒号、分钟采用固定的紧凑间距，不再拉伸铺满整列；第二城市时间明显放大，但保持主次层级。字体加载失败时回退到 Arial。许可随页面发布，见 `public/roboto-condensed-license.txt`。
- 第二城市采用城市名在上、时间在下的纵向布局，城市名称字号与主城市名称一致，时间适度放大，日期提示保留在时间旁；主城市仍保持最大的时间字号。
- 城市预设：赫尔辛基、西安、伦敦、罗弗敦群岛（Svolvær）、大阪。旧设置中的北京自动替换成西安，保留原有主次顺序；不会把北京天气缓存用作西安天气。
- 日期与星期旁显示当前中国节气，始终保留中文名称，不随界面语言切换；按北京时间的实际交节时刻切换，非节气当天也显示当前所处节气。使用 `lunar-javascript` 在本地计算，无需联网；计算结果缓存至下一次交节，避免每分钟重复运算。
- 「交换城市」交换两地时间、天气及主城市日出日落，不改变系统时区；已有天气缓存可直接复用。
- 设置中可选中文 / English、12 / 24 小时制和城市，独立记住各项选择。
- 「刷新天气」位于主页面天气栏最下方；设置面板的「完成」位于左下方。
- 主页面的交换城市、设置、刷新天气使用双向箭头、齿轮、刷新箭头图标按钮；点击区域为 44 × 44 CSS 像素。保留中英文悬停提示及无障碍名称，刷新时禁用按钮但不使用旋转动画。
- 两地共用的「更新于」放在刷新按钮右侧，按主城市时区显示。取两地成功更新时刻中较早的一个，避免仅一地刷新成功时误报整体已更新；部分失败、断网及过期提示也在此处集中显示。任一城市尚无数据时，统一更新时间显示为「—」。
- 默认「自动横向」：浏览器视口为竖向时将网页顺时针旋转 90°，横向时不旋转。也可明确选择不旋转、顺时针或逆时针。
- 两地当天逐小时温度折线、抽样降水概率、最高最低温。各自按城市当地日期展示。曲线从当前整点小时延伸到当天 23:00（例如 11:10 显示 11:00–23:00），每到整点自动移除前一小时的数据；横轴、降水概率及纵轴范围同步调整，只重绘缓存数据，不额外调用 API。23 点仅剩一个点时居中显示，午夜切换到新一天。最高最低温仍表示完整一天。
- 温度旁的天气描述：数据更新后的 90 分钟内采用 API 当前天气，之后使用当日预报描述与当前小时预报温度，避免把数小时前的实况标为实时天气。
- 天气按照固定的**赫尔辛基时间 06:00、12:00、18:00**检查更新；交换城市不改变这个日程。首次打开、增加城市及手动刷新可额外请求。
- API 每次获取今天与明天的预报，避免午夜产生额外的例行请求。
- 缓存使用 localStorage，更新失败保留旧数据，明确标记过期；失败后退避 15 分钟。无缓存时显示错误，时间仍可用。
- 主城市日出日落；极昼 / 极夜显示文字说明。
- 日出日落及晴、多云、阴、雾、雨、雪、雷暴、冰雹采用免费 [Lucide](https://lucide.dev/) 黑白 SVG 图标，保留中文 / 英文天气文字。只打包所用图标，无需字体文件、CDN 或额外网络请求。许可说明随构建一起发布，见 `public/lucide-license.txt`。

## GitHub Pages

项目已经包含 `.github/workflows/deploy.yml`，但没有创建仓库、上传或发布。

1. 创建 GitHub 仓库，将项目推送到 `main` 分支（包含 `pnpm-lock.yaml`）。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 工作流自动安装、测试、构建并发布 `dist/`。完成后在 Pages 页面查看网址。
4. Kindle 浏览器打开该网址。首次打开需要联网加载页面和天气。

`base: './'` 兼容仓库子路径，无需硬编码仓库名。若用于组织项目，正式部署前请与 infra 团队确认托管规范。

## Kindle 实机检查

具体型号未知，现代浏览器中的验证**不能证明旧 Kindle 一定兼容**。

1. 打开生产网页，确认中文字体、大时钟和两个图表都能显示。
2. 横着摆放 Kindle，按需选择顺时针 / 逆时针。旋转只影响网页，地址栏、原生下拉菜单和系统键盘不会随网页旋转。
3. 测试交换城市、中英文、12 / 24 小时制，重新打开后确认设置被保留。
4. 尽量收起浏览器工具栏，检查六寸屏的可用高度、按钮大小及图表字号。
5. 断网后点击「刷新天气」，应保留缓存并显示更新失败。重新联网后可手动刷新。
6. 让设备休眠并唤醒，确认时间和天气补查正常。网页不能保证阻止 Kindle 自动休眠，也无法在浏览器关闭或休眠时执行定时任务。

生产构建包含 legacy JavaScript 与运行时 polyfill，目标为 Safari 9 / Chrome 49 及以上。CSS 避免 Grid、Flex gap 和动画；仍需设备支持基础 Flexbox、SVG、HTTPS、跨域 XHR 及 JavaScript。更旧或受限的 Kindle WebKit 可能需要后续适配，legacy 构建不能补齐浏览器渲染或 TLS 能力。

时钟不依赖设备的系统时区或 `Intl`：五个预设城市使用固定偏移及现行欧盟夏令时规则。如果未来夏令时政策发生变化，需要更新 `src/model.js`。时间准确性仍取决于 Kindle 的系统时钟。

## 天气来源与边界

天气由 [Open-Meteo](https://open-meteo.com/) 提供，免费开放接口适合个人非商业使用，遵守其[使用条款](https://open-meteo.com/en/terms)与[许可说明](https://open-meteo.com/en/licence)。发布到商业环境或大量设备前应重新核对额度与授权。

页面设置面板保留来源链接。浏览器直接向 API 请求，两座城市通常各一次请求 / 刷新时段。不是分钟级实时天气，也不是后台推送。断网后已打开的页面能继续显示时间及缓存，但本项目没有实现离线加载整个网页的 Service Worker。

## 文件

- `src/main.jsx`：界面、设置、旋转、时钟与缓存刷新调度。
- `src/styles.css`：黑白看板和六寸屏紧凑样式。
- `src/model.js`：城市、时区、语言日期、刷新时段和预报处理。
- `src/weather.js`：带 20 秒超时的天气请求与响应校验。
- `src/WeatherIcon.jsx`：天气代码与本地 SVG 图标的对应显示。
- `src/weatherPresentation.test.jsx`：统一更新时间、部分失败状态与天气图标测试。
- `src/solarTerms.js`：节气计算、北京时间转换与固定中文名称。
- `src/solarTerms.test.js`：交节时刻、跨年、闰年及 24 节气名称测试。
- `src/model.test.js`：时区 / 夏令时、日期切换、缓存容错、预报与 API 单元测试。
- `vite.config.js`：静态子路径与旧浏览器构建。
